## Pending-page stepping in handle()

`handle()` builds `base` from `pending` and calls `press()` on it. When the result contains `go`, it restores the displayed `st.page` and `st.sub` and lets the roll replace them. When there is no `go` (toggles, digit entry), `st` takes the base values. The roll's final step sets `page` and `sub` again, so the end state is right. The visible effect is limited to a possible frame where the page number in state is ahead of the shown page. Browser use could not be checked in this sandbox.

## Deploy gating

The first `npm test` runs against the committed sample in `data/`, which is the only input that should block. The live-data rerun is informational. One caveat: if the live fetch step fails, `data/` keeps the previous snapshot, so the second test run then repeats the first and is harmless.
