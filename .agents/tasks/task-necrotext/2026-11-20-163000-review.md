# NecroText: Teletext revival static web app (v1)

A zero-dependency Teletext revival. Page generators produce 40x24 grids, a resolver turns control codes into cells, and a canvas UI draws them with CRT effects. Node scripts build `dist/`, serve it, and fetch live feeds. CI tests and deploys to GitHub Pages every 30 minutes. Module and data paths are relative, so a Pages subpath works. The canvas draw maths, hash handling and fetch script hold up under reading. Two problems should be fixed first: overlapping page-change timers in the browser, and a deploy that is gated on tests running against live data.

Watch for: (1) concurrent `go()` timers can land on the wrong page (confirmed); (2) `pages.yml` runs `npm test` on freshly fetched live data, so odd upstream text can block every deploy (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

Navigation is a pure state machine (`src/ui/nav.js`) driven by `public/app.js`. The page-roll animation in `go()` is the weak point. It starts a new `setInterval` per request and never cancels the previous one, so quick input produces races.

Data loads relative to the page with an embedded snapshot as fallback, which suits a Pages subpath. The fetch script keeps old snapshots on failure and records the failure for page 666, a good fit for the product. The deploy workflow then runs the property tests against whatever was just fetched. That makes the live site's freshness depend on upstream content.

Repo requirements are met: MIT LICENSE, `.kiro/` committed and not in `.gitignore`, README run steps, `docs/HOW_KIRO_WAS_USED.md`. No em dashes were found, and 59 tests pass locally.

<summary>Issues (5)</summary>

1. **Overlapping page-roll timers** (confirmed) - `go()` in `public/app.js` never clears the previous interval. Keep one module-level timer, clear it at the top of `go()`, and let the latest request win.
2. **Stale page on repeated stepping** (confirmed) - `handle()` calls `press()` with `st.page`, which only updates after the roll ends (about 360 ms). Two quick PG+ presses both go to the same page. Track a pending target page and step from it.
3. **Deploy gated on live-data tests** (likely) - In `.github/workflows/pages.yml`, `npm test` runs after `fetch-data`, and the property tests read `data/*.json`. A weird upstream title or an empty weather array can fail the test step and stop all deploys. Run tests before fetching, or on the bundled sample only.
4. **Browser shortcuts swallowed** (confirmed, minor) - The keydown handler calls `preventDefault` on every single-character key, including `/` (Firefox quick find) and space. Restrict it to keys the app uses (digits, r g y b x s c m h ? + - =).
5. **Empty settings files** (confirmed, trivial) - `.kiro/settings/permissions.json` and `.yaml` are zero bytes. Remove them or fill them in.

## Page-roll animation races

`go()` runs an 8-step interval at 45 ms. A second call while one is running starts a second timer. Both write `searching` and eventually call `load()`, so the page shown is whichever timer finishes last, not the last one requested. The same applies to `hashchange` firing during a roll. Separately, `handle()` computes ArrowUp/Down targets from `st.page`, which is not updated until the roll ends. Holding PG+ therefore lands on the same page repeatedly. A single `let rollTimer` cleared at the start of `go()`, plus a `pending` page used by `press()`, fixes both.

## Live-data tests in the deploy path

`tests/pages.property.test.js`, `tests/ghost.test.js` and `tests/ui.test.js` use `loadDataSync()` on the real `data/` directory. Locally that is the bundled sample. In `pages.yml` it is live BBC, Hacker News and Open-Meteo content. The invariants tested are the product's own, so failures would be real bugs, but they would surface as a missing deploy at 30-minute intervals. Catching those inputs is worth doing, but in a non-blocking step, with the blocking test run on the sample data.

## Key handling

The keydown filter lets `e.key.length === 1` through, then `preventDefault()`. Ctrl, Meta and Alt are excluded, which protects most browser shortcuts. Plain `/` and space are still blocked. Focused remote buttons also have their native Enter click replaced by `handle('Enter')`. That is fine since the result is the same key.

## Test coverage

Covered: grid invariants, text folding, mosaic, RSS parsing, ghost layer, nav state machine, fetch script with an injected fetch. Not tested: `public/app.js` itself (timers, hashchange, `loadData` fallback path), `draw.js` canvas output (it could not be viewed in a browser), and the workflow files. The canvas code reads correctly on inspection: mosaic bit layout, double-height clipping and the `#` to pound mapping all agree with the grid rules.
